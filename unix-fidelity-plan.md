# Heyming OS + jsh — improvement plan (Ralph backlog)

Living **gap list and priorities** for agentic loops. **Loop discipline, architecture rules, and copy-paste recipe** live in [`Ralph.md`](Ralph.md). This file answers: _what the product does today_, _what is still wrong or missing_, and _what to do next (one slice per loop)_.

---

## What “good” means here

We are not building POSIX in the browser. We **are** building:

1. **Credible jsh** — paths, pipes, redirects, `$?`, builtins that fail loudly on stderr with non-zero exits where users expect it.
2. **One real filesystem story** — same `FileSystemDB` paths for terminal, file manager, desktop, and apps; binary files (`contentBytes`) and text (`content`) both handled consistently in UI and tooling.
3. **Honest limits** — document what cannot exist (real bash, real ICMP, unbounded RAM for huge git packs).
4. **HTML / UI (when useful)** — improve markup, styling, and small interaction details when they make behavior easier to read, errors easier to notice, or the product feel closer to a real terminal/desktop. Prefer doing this **in the same loop** as a related shell, VFS, or OS change (same feature area), not drive-by redesigns.

## Major gaps (do not assume fixed)

**Shell language**

- ~~No `&&` / `||` / `;` lists~~ — **implemented** (`ShellUtils.splitShellList` + `processCommand`); left-associative like bash; syntax errors exit `2`. **Limitation:** no `&` background, no subshells.
- No globs, command substitution, job control; `2>&1` is supported as stderr→stdout merge (not full POSIX fd dup semantics).
- Variable expansion is not full bash (see [`terminal/README.md`](terminal/README.md)).

**Commands / coreutils**

- Many tools only read the **first** file operand; **`cat`** / **`head`** / **`tail`** / **`wc`** / **`sort`** take multiple **FILE**s where noted in the backlog. **`uniq`** uses **`INPUT [OUTPUT]`** (GNU-style; not multi-input like **`sort`**). Several commands still use naive flag parsing (`--` not universal) where not yet audited.
- Missing or thin vs GNU: **`sed`** has literal **`s///`** (with the same literal address forms as **`d`**, see backlog §102), **`;`**-separated command lists (same order as multiple **`-e`**, see backlog §99), unaddressed **`d`**, line-number **`d`**, **literal substring `/pat/d`**, and **literal `/pat1/,/pat2/d`** range deletes (see §95–§99). **`awk`**: **`{print ...}`** subset only — **`$0`/`$N`/`NR`/`NF`**, **`-F`**, stdin/FILEs (see backlog §57). **`xargs`**: subset (see backlog §56). **`stat`**: multi-line GNU-style summary (`File`, `Size`, `Access`, timestamps), **`-L`/`--dereference`**, **`--`**, **`--help`**; no `-c` / `--printf` (see [`terminal/commands/filesystem/stat.js`](terminal/commands/filesystem/stat.js), **`ShellUtils.parseStatArgv`**).

**Process model**

- `ps` / `kill` / `spawn` are simulated; document vs POSIX.

**Git / memory**

- Large clones can OOM the tab; shallow + `--no-checkout` + docs in `git --help`.

## Process model (jsh)

Not a real kernel. **`spawn`**, **`kill`**, **`ps`**, and **`top`** use `HeymingKernel.processManager` (Web Workers where “isolated”): PIDs and states are simulated; **`top`** CPU/memory/load are decorative unless wired to real metrics. **`kill`** returns stderr-only errors (success is silent on stdout, like many Unix `kill` implementations); **`ShellUtils.parseKillArgv`** centralizes argv parsing for tests. **`top --help`** / **`ps --help`** document the simulation; missing process manager yields a clear stderr and exit `1`.

### Ctrl+C vs `kill` (browser)

- **Ctrl+C** while a command line is running: handled in capture phase on `document` ([`terminal/terminal.js`](terminal/terminal.js) `beginBlockingCommandRun` / `endBlockingCommandRun`). It **`abort()`s** `runAbortSignal` only — it does **not** send a POSIX signal to worker “processes” or to arbitrary async work unless that work passes the signal into `fetch` (or similar). Long HTTP paths **`curl`**, **`git`**, **`ping`**, and the CORS **`proxyService`** merge **`runAbortSignal`** with timeouts so Ctrl+C cancels in-flight requests; exit **`130`** and **`^C`** output match the usual shell interrupt convention when the command propagates `AbortError`.
- **`kill PID`** / **`kill -SIGNAME PID`**: targets the **simulated** process table (`HeymingKernel.processManager`), not the browser’s own tabs or workers except where the model wires delivery. Use **`kill --help`** for supported signals and limits.
